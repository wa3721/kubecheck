3. 时序图Sequence

两级流程：第一级 Deployment informer 就绪超时→告警并直接退出（退出码 2）；第二级 waitForTargetPods 前置 → 逐 Pod「阶段2 waitPodRunning → 阶段3 watchPodLog」。优先级：Pod 异常 > 日志告警。

sequenceDiagram
    autonumber
    participant CLI as cobra / kubectl-check
    participant CHK as Checker
    participant K8S as client-go / K8s
    participant LR as LogErrorRecorder
    participant FS as 落盘文件 (.log)
    participant FA as FeishuAlert

    CLI->>CHK: Run(ctx, opts)
    Note over CHK: 第一级：waitDeploymentReady(ctx)
    CHK->>K8S: Deployment informer 监听 (deploy-ready-timeout)
WaitForCacheSync + 首次同步后补查
    alt rolloutComplete 命中（四条件）
        K8S-->>CHK: 就绪事件
    else 就绪超时
        CHK->>FA: 发送告警（Deployment 就绪超时）
        FA-->>CHK: 优先飞书 / 降级控制台
        Note over CHK: 直接退出（退出码 2，不进入第二级）
    end
    CHK->>K8S: waitForTargetPods（PodReadyTimeout 内 1s 轮询，等待 Pod 出现）
    loop 每个 Pod（阶段2 → 阶段3 串行）
        par 阶段2：Pod 状态轮询 waitPodRunning
            CHK->>K8S: 1s 轮询 Get（--pod-ready-timeout）
            K8S-->>CHK: Running / 超时未就绪
            alt 超时未进入 Running
                CHK->>FA: alert(EventPodStatus)
                CHK-->>CLI: 退出 code=3
            end
        and 阶段3（进入 Running 后）：watchPodLog 日志观察
            loop 实时日志流读取（--log-check-timeout）
                K8S-->>CHK: 日志行
                CHK->>LR: TrackLog（命中错误关键字 → errorHit）
                LR->>FS: 逐行增量追加落盘，错误行 ANSI 红色标注
            end
            par 退出检测（1s ticker）
                CHK->>K8S: containerExitCode / totalRestartCount
            end
            alt 容器异常退出（exit code != 0）
                CHK->>FA: alert(EventContainerExit) + waitLogFlush
                CHK-->>CLI: 退出 code=3
            else 重启次数超限
                CHK->>FA: alert(EventRestartLimit)
                CHK-->>CLI: 退出 code=3
            else 日志窗口结束且 errorHit（Pod 存活）
                CHK->>FA: alert(EventPendingCheck)「需要检查」（非阻塞）
                CHK-->>CLI: 退出 code=0
            else 日志窗口结束无错误
                CHK-->>CLI: 退出 code=0
            end
        end
    end

4. 状态图State

插件生命周期（无整体超时、无稳定窗口）：解析 → 第一级 Deployment informer 等待就绪（超时告警并直接退出）→ 第二级「阶段2 状态轮询 → 阶段3 日志观察」→ 按优先级判定场景（1/2/3）→ 退出。

    [*] --> Parsing : cobra Execute
    Parsing --> Checking : 参数合法
    Parsing --> [*] : 参数非法 / -h
    Checking --> Waiting : informer 缓存同步完成
    Waiting --> Monitoring : rolloutComplete 命中（四条件）
    Waiting --> [*] : 就绪超时 (告警后退出, code=2)
    Monitoring --> PodReady : Pod 在 pod-ready-timeout 内进入 Running
    Monitoring --> PodNotReady : Pod 未进入 Running / 容器退出 / 重启超限
    Monitoring --> LogHit : Pod 就绪且存活但日志命中错误
    PodNotReady --> [*] : 发送告警（EventPodStatus/ContainerExit/RestartLimit）, exit=3
    LogHit --> NotifyCheck : 日志窗口结束（日志已全程增量落盘）
    NotifyCheck --> [*] : 发送「需要检查」提醒 (非阻塞), exit=0
    PodReady --> [*] : 无错误日志, exit=0
    Monitoring --> [*] : 收到中断信号

5. 逻辑核对表Check Matrix

覆盖全部关键场景：行为 → 退出码 → 飞书告警。请逐行核对是否符合预期。

#场景插件行为退出码飞书告警
1 场景1：Pod 在 pod-ready-timeout 内就绪，无错误日志 正常结束 0 无
2 场景2：Pod 未进入 Running / 容器异常退出 / 重启超限 发送告警后异常退出（--max-restart 为 0 时不检查重启次数） 3 Pod 状态异常 / 容器异常退出 / 重启次数超限（优先飞书，降级控制台）
3 场景3：Pod 已就绪且存活但日志命中错误关键字 日志全程 Follow 实时流增量落盘（错误行红色标注），窗口结束后发送「需要检查」提醒 0 需要检查（非阻塞，不影响退出码）
4 第一级：Deployment 超时未就绪（rolloutComplete 四条件未满足） 告警后直接退出（不进入第二级） 2* Deployment 就绪超时（优先飞书，降级控制台）
5 命中忽略关键字（--log-ignore-keywords） 仍追加落盘但不标红、不作为错误，继续追踪 - 无
6 未产生任何 Pod 按 Pod 状态异常处理，发送告警后异常退出 3 未产生 Pod（优先飞书，降级控制台）
7 参数非法 / 客户端构建失败 / 查询失败 终止（返回错误并退出） 1 无
8 未配置飞书 Webhook（--feishu-webhook 为空） 所有告警事件降级为控制台直接打印（[ALERT][事件类型]），不静默丢弃；退出码与判定逻辑不变 - 控制台打印替代飞书推送
9 收到中断信号（Ctrl+C / SIGTERM） Interrupt()：取消上下文 → 等待收尾 → 发送 EventInterrupted 告警后退出，不误报为业务错误 130 检查被中断（EventInterrupted）

6. 关键设计决策Decisions

  • 命令行框架 cobra：github.com/spf13/cobra，遵循 kubectl 原生参数风格。
  • 两级独立检查，无整体超时：三段超时 --deploy-ready-timeout / --pod-ready-timeout / --log-check-timeout 相互独立，无顶层兜底超时、无 stable 稳定窗口。
  • 第一级 Deployment 就绪超时直接中断：informer 事件驱动 + rolloutComplete 四条件判定；超时未就绪发送告警（优先飞书 / 降级控制台）后，以退出码 2 直接退出，不再进入第二级 Pod 检查。
  • 第二级为轮询实现：Pod 侧不使用 informer，waitForTargetPods / waitPodRunning / 退出检测均为 1s 间隔 List/Get 轮询；仅第一级 Deployment 使用 informer 事件驱动。
  • 优先级：Pod 异常 > 日志告警：场景2（Pod 未进入 Running / 容器退出 / 重启超限）→ 告警 + 异常退出 code=3；即便同时命中错误日志也按场景2。
  • 场景3：Pod 就绪且存活但日志命中错误：日志全程增量落盘（错误行红色标注），日志窗口结束后发送「需要检查」提醒，不退出（code=0，非阻塞）。
  • Follow 实时流增量追加写（O_APPEND）：文件恒保存日志流采集到的全部日志（非仅错误行）；同 Pod 新日志按时间顺序持续追加，新旧错误共存于同一文件，无需重复拉取。
  • 错误行红色标注：命中 --log-err-keywords 的行以 ANSI \x1b[31m...\x1b[0m 标红；忽略行不标红。
  • 告警非阻塞：飞书发送独立 goroutine + 短超时，失败仅 warning，不影响主流程判定与退出码。
  • 未配置 Webhook 降级控制台：--feishu-webhook 为空时，所有告警事件降级为控制台直接打印（带去重），不静默丢弃；退出码与判定逻辑不变。
  • 退出码 130 = 中断主动退出：收到 SIGINT/SIGTERM 触发 Interrupt()：取消上下文 → 等待收尾 → 发送 EventInterrupted 告警后退出，不误报为业务错误。
  • 时间参数秒级化：--deploy-ready-timeout / --pod-ready-timeout / --log-check-timeout / --feishu-dedup-window 统一为整数秒（int 秒）。
  • 文件命名：{namespace}-{podName}-{date}.log（date=20060102，跨天自动切换）。
