2主流程编排（目标定位 + 两阶段独立检查）

两段超时彼此独立、无整体超时；目标定位在 --pod-ready-timeout 窗口内轮询等待目标 Pod 出现（不校验 Deployment 超时与滚动状态，覆盖"发布刚触发、新 RS 已创建但 Pod 尚未创建"的竞态窗口），replicas=0 无目标可等或窗口内未出现直接退出（code=2）不再进入后续阶段；--check-pod-status=false 时目标定位完成即通过。虚线为告警旁路，不阻塞主流程。

3单 Pod 并行追踪（trackPod 内部）

Pod 首次进入 Running 时即启动阶段3 watchPodLog（与阶段2 的 Ready 等待并行：有探针时 0/1 Running 期间两阶段共同作用，任一终态经 podCtx 联动取消另一路）；watchPodLog 内部「日志流」与「退出检测」两路并行，各自独立超时。controller 删除中的 Pod（surge 缩容/回滚）静默跳过不计异常。--log-enable=false 或 --log-check-timeout=0 时跳过阶段3。

7退出码约定

Code含义触发路径（对应代码）
0成功目标 Pod 全就绪且无真错误日志（场景1）；或就绪且存活但存在真错误日志（场景3，已提醒；--log-dump 开启时已全量落盘）；或 --check-pod-status=false（目标定位完成即通过）
1参数 / 环境错误parseArgs 非法、buildClient 失败、listTargetPods 资源查询失败、cobra RunE 返回错误
2未找到目标 Pod目标定位 locateTargetPods 未找到目标 Pod（replicas=0 无目标可等，或 pod-ready-timeout 窗口内目标 Pod 未出现；已发 EventNoTargetPod 告警，不进入阶段2/3）
3Pod 异常任一 Pod 未就绪（Ready 超时）/ 容器异常退出 / 重启次数超限（已发对应告警 EventPodStatus / EventContainerExit / EventRestartLimit）
130用户中断SIGINT / SIGTERM 触发 signal goroutine → Interrupt()：取消上下文 → 等待收尾 → 发送 EventInterrupted 告警后退出（与 shell 约定一致）

9设计与实现关键差异（对照 kubectl-check-uml.html / SPEC）

以下为对照当前代码后确认的、以实际实现为准的差异点（设计文档按此同步修正）：

#历史版本描述（旧）当前代码实际行为
1 阶段1 等待 Deployment 滚动收敛（rolloutComplete 四条件，informer 事件驱动），收敛通过后阶段2 等 Pod Running；后改为 lockTargetPods 三分支轮询 不再校验 Deployment 的超时与滚动状态，目标定位 locateTargetPods 在 pod-ready-timeout 窗口内轮询等待最新 revision RS 的目标 Pod 出现（含 Pending，覆盖"发布刚触发、新 RS 已创建但 Pod 尚未创建"的竞态窗口）后进入 Pod 层级校验；lockTargetPods/rolloutComplete 轮询已删除，--deploy-ready-timeout 参数已移除
2 阶段2 判定为 Status.Phase == Running 升级为 waitFirstRunning + waitReady：PodReady 条件 == True（等价 podutil.IsPodReady，含就绪探针校验；无探针容器 Running 即就绪），弥补旧阶段1 隐含的探针校验能力；阶段3 从首次 Running 启动（与阶段2 并行，podCtx 联动取消），日志窗口锚点为首次观察到 Running 的时刻
3 退出码 2 = 滚动收敛超时 / 目标锁定超时；「未产生任何 Pod」为独立告警路径（code=3） 退出码 2 = 未找到目标 Pod（listTargetPods 返回空，如 replicas=0）；「未产生任何 Pod」路径并入该语义
4 错误日志为 Follow 实时流逐行增量追加写（O_APPEND），--log-dump 开启时命中关键字即落盘 按 LLM 启用与否双路径：默认（LLM 仲裁）命中行经智谱 GLM 批量判定，真错误才 SinceTime 全量快照覆盖写（O_TRUNC）；禁用（--llm-endpoint=""）保持旧关键字即真 + 增量追加行为
5 无 LLM 能力；日志告警以关键字命中为准 新增 internal/llm 包（OpenAI 兼容，标准库实现，默认端点智谱 GLM/GLM-4-Flash-250414，后随 --llm-enable/--keyword-check 开关引入改为默认关闭）；调用失败降级关键字即真，连续 3 次失败熔断；warning 告警与落盘同门槛（仅真错误）
6 锁定/追踪期间 Pod 被删除（surge 缩容、回滚）会被计为异常 阶段2（NotFound / DeletionTimestamp → 静默跳过）与阶段3 退出检测（删除中 Pod 豁免）双重防误报：controller 删除的 Pod 不计为应用故障
7 util.go 与 internal/finish 包存在 util.go 与 finish 包均已删除，逻辑并入 checker.go / cmd.go；无收尾目录扫描
8 日志跟踪立即读取容器日志 TrackLog 前先 waitForContainerRunning 轮询等待容器进入 Running（1s 间隔），避免日志流过早打开
