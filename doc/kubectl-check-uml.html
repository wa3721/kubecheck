核心类：cobra 命令（入口）→ Checker（编排）→ LogErrorRecorder（落盘）→ FeishuAlert（告警）。

3. 时序图Sequence

目标定位 + 两阶段流程：目标定位（locateTargetPods 轮询等待目标 Pod 出现）未找到目标 Pod → 告警并直接退出（退出码 2）；定位后逐 Pod「waitFirstRunning 等首次 Running → 并行：阶段2 waitReady 就绪等待 + 阶段3 watchPodLog 日志观察（LLM 仲裁 + 退出检测）」（有探针时 0/1 Running 期间共同作用，任一终态 podCtx 联动取消另一路）。优先级：Pod 异常 > 日志告警。

sequenceDiagram
    autonumber
    participant CLI as cobra / kubectl-check
    participant CHK as Checker
    participant K8S as client-go / K8s
    participant LR as LogErrorRecorder
    participant LLM as LLM 仲裁（--llm-enable 开启, 默认端点智谱 GLM）
    participant FS as 落盘文件 (.log，--log-dump 开启时)
    participant FA as FeishuAlert

    CLI->>CHK: Run(ctx, opts)
    Note over CHK: 目标定位：locateTargetPods(ctx) 轮询等待目标 Pod 出现
    CHK->>K8S: Get Deployment（判 replicas）+ List RS + List Pods
（最新 revision RS selector，不校验 Deployment 状态）
    alt 目标 Pod 出现（Pending 即算定位成功）
        K8S-->>CHK: 目标 Pod 名单
    else 未找到目标 Pod（replicas=0 / 窗口超时）
        CHK->>FA: 发送告警（未找到目标 Pod）
        FA-->>CHK: 优先飞书 / 降级控制台
        Note over CHK: 直接退出（退出码 2，不进入阶段2/3）
    end
    loop 每个 Pod（阶段2/3 并行：首次 Running 启动阶段3）
        CHK->>K8S: waitFirstRunning 等首次 Running（--pod-ready-timeout 前半）
        K8S-->>CHK: Running（锚点 runningAt）
        Note over CHK: 并行启动阶段2 Ready 等待 + 阶段3 日志观察
（podCtx 联动：任一终态取消另一路）
        par 阶段2：Pod 就绪轮询 waitReady
            CHK->>K8S: 1s 轮询 Get（--pod-ready-timeout 剩余预算）
            K8S-->>CHK: PodReady 条件 / removed / 超时
            alt 超时未就绪
                CHK->>FA: alert(EventPodStatus)「未就绪」（取消阶段3）
                CHK-->>CLI: 退出 code=3
            else removed（controller 删除，surge/回滚）
                Note over CHK: 静默跳过（非应用故障）
            else 就绪（阶段2 结束，阶段3 继续至窗口结束）
                Note over CHK: 无探针容器通常秒级就绪
            end
        and 阶段3（首次 Running 即启动）：watchPodLog 日志观察
            loop 实时日志流读取（--log-check-timeout）
                K8S-->>CHK: 日志行
                CHK->>LR: TrackLog（命中行 → 仲裁 / 关键字判定）
                alt LLM 启用（默认）
                    LR->>LLM: 攒批(10行/2s)+去重 → Judge 批量判定
                    alt 任一真错误
                        LR->>K8S: GetLogs(SinceTime=容器启动时刻)
                        LR->>FS: 全量快照覆盖写（错误行 ANSI 红色标注）+ errorHit
                    else 全部假错误
                        Note over LR: 不落盘不告警
                    else 调用失败
                        LR->>FS: 降级关键字即真（连续3次失败熔断）
                    end
                else LLM 禁用（--llm-endpoint=""）
                    LR->>FS: 命中即落盘（缓冲 + 增量追加，--log-dump 开启时）
                end
            end
            par 退出检测（1s ticker，删除中 Pod 豁免）
                CHK->>K8S: containerExitCode / totalRestartCount
            end
            alt 容器异常退出（exit code != 0，含 Ready 前崩溃）
                CHK->>FA: alert(EventContainerExit) + waitLogFlush（取消阶段2）
                CHK-->>CLI: 退出 code=3
            else 重启次数超限
                CHK->>FA: alert(EventRestartLimit)
                CHK-->>CLI: 退出 code=3
            else 日志窗口结束且 errorHit（Pod 存活）
                CHK->>FA: alert(EventPendingCheck)「需要检查」（非阻塞）
                CHK-->>CLI: 退出 code=0
            else 日志窗口结束无真错误
                CHK-->>CLI: 退出 code=0
            end
        end
    end

4. 状态图State

插件生命周期（无整体超时、无稳定窗口）：解析 → 阶段1 目标锁定（超时告警并直接退出）→「阶段2 就绪等待 → 阶段3 日志观察 + LLM 仲裁」→ 按优先级判定场景（1/2/3）→ 退出。

    [*] --> Parsing : cobra Execute
    Parsing --> Locking : 参数合法
    Parsing --> [*] : 参数非法 / -h
    Locking --> Monitoring : 三分支锁定目标 Pod（收敛有 Pod / 等到更新 / 谓词满足）
    Locking --> [*] : 锁定超时 (告警后退出, code=2)
    Monitoring --> PodReady : Pod 在 pod-ready-timeout 内就绪（PodReady 条件）
    Monitoring --> PodNotReady : Pod 未就绪 / 容器退出 / 重启超限
    Monitoring --> Removed : Pod 被 controller 删除（surge/回滚）
    Removed --> [*] : 静默跳过（非故障）
    Monitoring --> LogHit : Pod 就绪且存活但存在真错误日志
    PodNotReady --> [*] : 发送告警（EventPodStatus/ContainerExit/RestartLimit）, exit=3
    LogHit --> NotifyCheck : 日志窗口结束（--log-dump 开启时 SinceTime 全量日志已落盘）
    NotifyCheck --> [*] : 发送「需要检查」提醒 (非阻塞), exit=0
    PodReady --> [*] : 无真错误日志, exit=0
    Monitoring --> [*] : 收到中断信号
发送 EventInterrupted 告警, exit=130

5. 逻辑核对表Check Matrix

覆盖全部关键场景：行为 → 退出码 → 飞书告警。请逐行核对是否符合预期。

#场景插件行为退出码飞书告警
1 场景1：Pod 在 pod-ready-timeout 内就绪，无真错误日志 正常结束 0 无
2 场景2：Pod 未就绪（Ready 超时）/ 容器异常退出 / 重启超限 发送告警后异常退出（--max-restart 为 0 时不检查重启次数） 3 Pod 状态异常 / 容器异常退出 / 重启次数超限（优先飞书，降级控制台）
3 场景3：Pod 已就绪且存活但日志存在真错误（LLM 仲裁确认或降级命中） --log-dump 开启时 SinceTime 全量快照落盘（错误行红色标注），窗口结束后发送「需要检查」提醒；全部假错误则不落盘不告警 0 需要检查（非阻塞，不影响退出码；仅真错误触发）
4 目标定位未找到目标 Pod（replicas=0 无目标可等，或 pod-ready-timeout 窗口内未出现） 告警后直接退出（不进入阶段2/3） 2* 未找到目标 Pod（优先飞书，降级控制台）
5 命中忽略关键字（--log-ignore-keywords） 不参与仲裁/判定、落盘时不标红，继续追踪 - 无
6 发布刚触发（新 RS 已创建但 Pod 尚未出现）或滚动进行中启动 轮询等待目标 Pod 出现（含 Pending）后进入阶段2/3，竞态窗口不误判、慢启动应用早期日志不丢失；surge 临时副本被删除时静默豁免 - 无（仅删除中 Pod 豁免，不误报）
7 参数非法 / 客户端构建失败 / 查询失败 终止（返回错误并退出） 1 无
8 未配置飞书 Webhook（--feishu-webhook 为空） 所有告警事件降级为控制台直接打印（[ALERT][事件类型]），不静默丢弃；退出码与判定逻辑不变 - 控制台打印替代飞书推送
9 收到中断信号（Ctrl+C / SIGTERM） Interrupt()：取消上下文 → 等待收尾 → 发送 EventInterrupted 告警后退出，不误报为业务错误 130 检查被中断（EventInterrupted）

6. 关键设计决策Decisions

  • 命令行框架 cobra：github.com/spf13/cobra，遵循 kubectl 原生参数风格。
  • 仅校验 Pod 层级，无整体超时：不校验 Deployment 的超时与滚动状态（无 --deploy-ready-timeout）；两段超时 --pod-ready-timeout（目标定位等待 + Pod 就绪）/ --log-check-timeout（日志观察）相互独立，无顶层兜底超时、无 stable 稳定窗口。
  • 目标定位等待目标 Pod 出现而非收敛等待：locateTargetPods 在 pod-ready-timeout 窗口内 1s 轮询等待最新 revision RS 的目标 Pod 出现（含 Pending，覆盖"发布刚触发、新 RS 已创建但 Pod 尚未创建"的竞态窗口），不校验 rolloutComplete/observedGeneration 等滚动状态；replicas=0 或窗口内未出现，发送告警（优先飞书 / 降级控制台）后以退出码 2 直接退出。
  • 轮询实现：阶段2/3 为 1s 间隔 List/Get 轮询（informer 已删除）；轮询比事件组合简单、可测。
  • 阶段2 就绪判定含探针校验：waitFirstRunning + waitReady 等待 PodReady 条件 True（无探针容器 Running 即就绪）；阶段3 从首次 Running 启动与阶段2 并行（有探针时 0/1 Running 期间共同作用，Ready 前容器崩溃立即告警）；controller 删除中的 Pod（surge 缩容/回滚）静默豁免不计异常。
  • 优先级：Pod 异常 > 日志告警：场景2（Pod 未就绪 / 容器退出 / 重启超限）→ 告警 + 异常退出 code=3；即便同时存在真错误日志也按场景2。
  • LLM 日志错误仲裁（--llm-enable 开启，默认关闭）：命中行进 pod 级有界 channel，攒批（10 行/2s）+ 去重后经 OpenAI 兼容协议（默认端点智谱 GLM，标准库实现，非流式 temperature=0）批量判定；存在任一真错误才置 errorHit（--log-dump 开启时以容器启动时刻为起点 SinceTime 全量拉取覆盖写快照）；调用失败降级关键字即真，连续 3 次失败熔断；--llm-enable=false（默认）或 --llm-endpoint="" 回退关键字即真行为。
  • 场景3：Pod 就绪且存活但存在真错误日志：日志窗口结束后发送「需要检查」提醒，不退出（code=0，非阻塞）；告警与落盘同门槛（仅真错误），落盘受 --log-dump 开关控制（默认关闭，开启时 SinceTime 全量日志落盘、错误行红色标注）。
  • 错误行红色标注：命中 --log-err-keywords 的行以 ANSI \x1b[31m...\x1b[0m 标红；忽略行不标红。
  • 告警非阻塞：飞书发送独立 goroutine + 短超时，失败仅 warning，不影响主流程判定与退出码。
  • 未配置 Webhook 降级控制台：--feishu-webhook 为空时，所有告警事件降级为控制台直接打印（带去重），不静默丢弃；退出码与判定逻辑不变。
  • 退出码 130 = 中断主动退出：收到 SIGINT/SIGTERM 触发 Interrupt()：取消上下文 → 等待收尾 → 发送 EventInterrupted 告警后退出，不误报为业务错误。
  • 时间参数秒级化：--pod-ready-timeout / --log-check-timeout / --llm-timeout / --feishu-dedup-window 统一为整数秒（int 秒）。
  • 文件命名：{namespace}-{podName}-{date}.log（date=20060102，跨天自动切换）。
  • LLM 安全：默认 API Key 内置于源码（仓库公开需轮换）；日志行发送至配置端点（默认云端），敏感场景指向内网自建端点；API Key 不落日志。
