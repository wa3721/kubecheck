7退出码约定

Code含义触发路径（对应代码）
0成功Deployment 就绪 + Pod 全就绪无错误日志（场景1）；或就绪且存活但存在错误日志（场景3，已提醒）；或 --check-pod-status=false
1参数 / 环境错误parseArgs 非法、buildClient 失败、waitForTargetPods 查询失败、cobra RunE 返回错误
2Deployment 就绪超时waitDeploymentReady 在 --deploy-ready-timeout 内 rolloutComplete 未满足（已发 EventDeployTimeout 告警，不进入第二级）
3Pod 异常waitForTargetPods 超时无 Pod，或任一 Pod 未进入 Running / 容器异常退出 / 重启次数超限（已发对应告警 EventPodStatus / EventContainerExit / EventRestartLimit）
130用户中断SIGINT / SIGTERM 触发 signal goroutine → Interrupt()：取消上下文 → 等待收尾 → 发送 EventInterrupted 告警后退出（与 shell 约定一致）

9设计与实现关键差异（对照 kubectl-check-uml.html / SPEC）

以下为对照当前代码后确认的、以实际实现为准的差异点（设计文档按此同步修正）：

#设计文档描述（旧）当前代码实际行为
1 第一级就绪判定使用 --for 指定 Condition（默认 Available） 无 --for 参数；就绪判定为 rolloutComplete 四条件（observedGeneration/updatedReplicas/readyReplicas 与 spec.replicas 对齐）
2 第二级 Pod 侧使用 informer 监听生命周期事件 Pod 侧无 informer：waitForTargetPods / waitPodRunning / 退出检测均为 1s 轮询 Get；仅第一级 Deployment 使用 informer
3 waitPodReady 含 10s 稳定性复查；isPodReady 要求 restartCount==0 均已移除：waitPodRunning 仅判断 Status.Phase == Running，无稳定窗口与重启次数前置要求
4 错误日志为「完整快照覆盖写」（SnapshotLogErrors / O_TRUNC / SinceTime 拉取） 改为 Follow 实时流逐行增量追加写（O_APPEND）：全程采集、错误行标红，无快照拉取
5 退出码含 4（日志错误根因）与 5（整体超时）；存在 --timeout / --stable-duration 无退出码 4/5、无 --timeout / --stable-duration：三段独立超时，退出码仅 0/1/2/3/130；容器异常退出归入 3
6 中断（130）不发送告警 Interrupt() 会发送 EventInterrupted 告警后退出；事件常量共 6 个（含 EventContainerExit / EventInterrupted），无 EventLogRootCause / EventReadyTimeout / EventOverallTimeout
7 util.go（watchDeployment/deploymentReady/isPodReady 等）与 internal/finish 包存在 util.go 与 finish 包均已删除，逻辑并入 checker.go / cmd.go；无收尾目录扫描
8 日志跟踪立即读取容器日志 TrackLog 前先 waitForContainerRunning 轮询等待容器进入 Running（1s 间隔），避免日志流过早打开
